# Handoff brief

Read this first when starting a new session or switching models. It says what this
project is, where it stands, how to run it, and the rules to keep.
Last updated: 2026-10-26, after Block 15 (staff assistant). Open review findings are listed under "Open issues" below: read them before starting.

## What this is
RistoManager Cloud: a multi-tenant web service for restaurants (reservations, floor plan,
menu, orders, a live kitchen screen). It is the web rewrite of a desktop Java app that is
frozen on branch `uniVersion`. It is a learning-and-portfolio project by AJ (GitHub: d4b0mb),
a part-time waiter and CS student. AJ wants plain English, short answers, real engineering
quality, and an explanation of what was done, why, and the trade-offs.

## Rules to keep
- Work only on branch `ristomanager-cloud`. Never touch `uniVersion`.
- Commits must be authored as `d4b0mb <mohamed.alagami18@gmail.com>`, with no co-author or
  tool attribution lines, so contributions show on AJ's GitHub graph.
- Do not open pull requests unless asked.
- Check CI after each push. Do not trust a green build until you have seen the tests run.
- Restart the backend after rebuilding its jar (a running JVM breaks if its jar is replaced).

## Stack
Java 21, Spring Boot 4.1, Maven, PostgreSQL 17 + Flyway (backend). Next.js 16 (React 19,
TypeScript, Tailwind 4, next-intl) in `frontend/`. Docker Compose locally; k3s planned for
production (Phase 3). GitHub Actions CI. Reasons for each choice: `docs/adr/`.

## How to run and test
- Backend tests (need Docker running): `cd backend && ./mvnw verify`
- Update the API contract after changing the API: `UPDATE_OPENAPI=true ./mvnw verify -Dit.test=OpenApiContractIT`,
  then `cd frontend && npm run api:types`, review and commit both.
- Frontend checks: `cd frontend && npm run lint && npm run typecheck && npm test && npm run build`
- Browser tests (stack must be up with demo data): `cd e2e && npm ci && npx playwright install chromium && npx playwright test`
- Whole thing: `docker compose up --build` then open http://localhost:3000
- Run by hand: start PostgreSQL (`docker compose up -d db`), run the backend jar, then
  `BACKEND_URL=http://localhost:8080 npm run start` in `frontend/`.

## Known gaps (be honest about these)
- Two restaurants share one system (Trattoria Demo and Duodecim Pizze) with look-alike logins: edits made as `owner@duodecim...` are invisible to `waiter@demo...`. Use the `duodecim` logins for the pizzeria.
- Options have no per-dish restriction (they apply to a whole course) and no "required choice"; a bill total is only an estimate on the order screen.
- The Duodecim allergens are a draft from ingredient lists; the pizzeria must confirm them.
- Servings are strictly in order (no "send serving 2 now"). Menu order is insertion order (no drag to reorder).
- Wake lock needs https or localhost; on plain http the tablet's own screen timeout applies.
- Voice (listening and speaking) is only research (`docs/VOICE_RESEARCH.md`) and two empty seams. Floor plan from a photo is proven on a drawn plan only.
- Assistant: proposals live in memory (one backend instance, a restart forgets them); it cannot edit a booking, take an order or answer from history by day; the prompt is tuned for the 9b model only; the Italian texts are AI-written.
- Floor plan editor: no multi-select, no drag-from-palette (tap adds at the middle of the view), left/top room edges do not stretch, one level of undo, and no undo for add/delete/room size.
- No login lockout (by choice; failed sign-ins are logged). Recovery attempts are throttled in memory, per API instance.
- Security questions are a weak recovery method; recovery codes would be stronger.
- Italian text for the Block 9 screens was written by the AI and needs a native read.
- Live stream fan-out is in memory: one API instance only. See ADR 0005 for the upgrade path.
- Order/ticket history by day is not exposed (only the active queue).
- A deactivated user keeps access up to 15 minutes (access token lifetime).
- The Docker images and the full compose stack were first built by CI, not in the author's sandbox (Docker Hub rate limits). If CI e2e fails, start there.
- Production server setup (deploy/) is untested on a real server.
- Public booking site (Phase 4) and Kubernetes (Phase 3) are not started.

## Lessons worth remembering
- Never cap the output of a long `docker run` with `Select-Object -First N` in PowerShell: when the cap is reached the pipe closes and the run is cut off (it looks like a failure, and the container may keep running on its own). Filter, then use `-Last`.
- `node --test` on Windows needs a file pattern (`node --test "dir/*.test.mjs"`), not a folder. A raw U+2028 or U+2029 inside a JavaScript regex literal is a syntax error: write the escape.
- Browser tests must not depend on the time of day: make the data they need themselves, for a day that is always in the future (tomorrow), never on the seeded "later tonight" bookings.
- Jackson 3: `JsonNode.textValue()` THROWS for a number or object (it does not return null). Read model or client JSON through `common/Json.text(node)`.
- `docker compose up --build frontend` also rebuilds and restarts `backend` (it is a dependency), so the backend you test is the one in your working tree.
- The browser pane's coordinate clicks are flaky while the page is still loading: focus a field with a script, then type; check results by reading the dialog text.
- Assistant evaluation must pace itself (`run-endpoint.mjs` waits 5.6 s) or it trips the 12 per minute limit.
- On the author's Windows PC (Java 25) JUnit tests that open a local socket fail with "Unable to establish loopback connection". Run the backend tests in Linux instead: `docker run --rm -v "$PWD:/w" -v "$HOME/.m2/repository:/root/.m2/repository" -w /w/backend maven:3.9-eclipse-temurin-21 mvn -B test` (for `verify` also mount `//var/run/docker.sock` and set `TESTCONTAINERS_HOST_OVERRIDE=host.docker.internal`, `TESTCONTAINERS_RYUK_DISABLED=true`). In PowerShell quote `-Dit.test=...` or the dot splits it.
- A small local model with thinking off will say "done" without calling the tool: keep thinking on for the assistant, and let code (not the model) do date arithmetic and safety rules.
- The demo seed makes a reservation "10 minutes ago": on an old database the allergy e2e tests fail. Reset with `docker compose down -v` and reseed.
- A module imported by a server component must not be marked "use client": its constants arrive as client references (this broke the "before first paint" scripts; they live in `lib/early-scripts.ts`).
- Floor plan tools sit in a left rail on big screens; stacking them above the plan pushed it off-screen again (the 1080p test catches it).
- Playwright `getByLabel("Password")` also matches any button whose aria-label contains "password": give icon buttons screen-reader text instead of an aria-label.
- A green build can hide skipped tests: always confirm tests actually ran (Failsafe for `*IT`).
- Rebuilding the backend jar while it runs breaks the running JVM: restart after every rebuild.
- `pkill -f <text>` kills your own shell if the text is in your command line: kill by process id or `fuser -k <port>/tcp`.
- `mvn verify` rewrites the jar: restart a running backend afterwards. The sandbox needs `dockerd` started by hand for the integration tests.
- JdbcClient `.single()` rejects a null row: `min()` over nothing needs `.list().get(0)`.
- POSIX `read` with a whitespace IFS (tab) merges empty fields; the menu file uses `|` for that reason.
- A new response type must be added to `OpenApiConfig.RESPONSES` or its fields become optional in the TS types.
- Run it for the whole restaurant: `docs/LOCAL_SERVER.md`. Phone on the same Wi-Fi: use the PC's LAN IP (`http://192.168.x.x:3000`), not localhost, and allow port 3000 in the PC firewall.
- OpenAPI merges two Java types with the same simple name into one schema (guarded by a test).
- `ResultSet.wasNull()` only describes the last column read: use `getObject(col, Integer.class)`.
- Playwright: `getByRole("alert")` also matches Next.js's route announcer; the orders and kitchen
  pages hold a live stream open, so "network idle" never happens.
